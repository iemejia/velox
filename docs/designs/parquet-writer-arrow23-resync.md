# Re-syncing the vendored Parquet writer to Apache Arrow 23

## Status

Proposal. The mechanical build adaptation to Arrow 23.0.1 has already landed
(`build(parquet): Upgrade Apache Arrow to 23.0.1`); this document plans the
follow-on work of re-syncing the vendored writer's *logic* to Arrow 23's
parquet-cpp.

## Background

Velox vendors a copy of Apache Arrow's C++ Parquet writer under
`velox/dwio/parquet/writer/arrow/`, rehomed into the
`facebook::velox::parquet::arrow` namespace with Velox naming and coding
conventions. The copy was taken from Arrow **15.0.0**. Velox builds Arrow with
`-DARROW_PARQUET=OFF` and compiles this vendored source itself rather than
linking `libparquet`.

Two Velox-specific divergences make the fork permanent:

- **FBThrift.** PR #16019 (June 2026) removed the external Apache Thrift
  dependency and moved the Parquet reader and writer to FBThrift. Thrift
  metadata types now come from `facebook::velox::parquet::thrift` (generated by
  `add_fbthrift_cpp_library` from `parquet.thrift`), consumed through
  `ThriftInternal.h`.
- **Velox features.** The fork carries byte-based row-group flushing
  (`FileWriter::finishRowGroup`, `currentRowGroupTotalBytes`), Iceberg data-file
  statistics, INT96 negative-nanosecond handling, and timestamp row-group
  filtering support.

## Why not link OSS `libparquet`

Linking Arrow's `libparquet` (i.e. `ARROW_PARQUET=ON`) is not viable while the
reader uses FBThrift. `libparquet` mandates Apache Thrift —
`parquet/thrift_internal.h` includes `<thrift/protocol/TCompactProtocol.h>` and
uses `apache::thrift::transport::TMemoryBuffer`, and its build compiles
Thrift-generated `parquet_types.cpp`. FBThrift and Apache Thrift both occupy the
`apache::thrift::` namespace with incompatible definitions (for example
`apache::thrift::TApplicationException` and `TMemoryBuffer`), so they cannot
coexist in one binary. This is the `TMemoryBuffer` ODR conflict already noted in
`CMake/FindArrow.cmake`. Adopting `libparquet` would require reverting the
reader to Apache Thrift and undoing #16019.

Keeping the FBThrift fork and re-syncing its source to Arrow 23 avoids the
conflict.

## Reframing: port semantics, do not re-vendor wholesale

A file-by-file re-vendor from Arrow 23 would reintroduce large mechanical churn
— license-header rewrites, comment reformatting, `parquet::` →
`facebook::velox::parquet::arrow`, snake_case → camelCase — for little value and
high regression risk against a working, tested baseline (861 tests pass on Arrow
23 today). Much of the raw 15→23 diff is exactly this mechanical layer, or
changes that either do not apply to Velox (Apache Thrift, `arrow/util/logging.h`
→ non-installed `logging_internal.h`) or were already handled by the build
adaptation.

The valuable work is to port the **semantically meaningful** upstream changes —
correctness fixes first, then features — onto the fork, translated to Velox
conventions. Treat it like cherry-picking upstream commits, not re-basing the
whole tree.

  - `size_statistics.{cc,h}` — size statistics (enabled by default since Arrow 20).
  - `chunker_internal.*` — content-defined chunking (Arrow 20).
  - `geospatial/`, `variant_internal.*` — new logical types.
  - `level_conversion_bmi2_internal.h`, `level_comparison_avx2_internal.h`.

## Prioritized backlog

**P0 — correctness fixes (writer-applicable):**

- **[Done]** Invalid Parquet written when dictionary-encoded pages are large —
  Arrow 23, GH-47973. Ported into `RleEncoder`, `LevelEncoder`, the dictionary
  encoder, and `BitWriter` (int64 buffer-size math with `int32` guards).
- **[Done]** Pre-1970 INT96 timestamp round-trip — GH-48246. Velox's writer
  already borrows a day for negative intra-day remainders (commit `edfee872c`),
  equivalent to the upstream fix. No production change; added the upstream
  conversion vectors as a regression test that previously had no coverage.

**Investigated — do not map to the vendored fork:**

- Non-compliant RLE stream compatibility — GH-47981. The fix lives in Arrow's
  rewritten `RleBitPackedParser`/`RleBitPackedDecoder`, which postdate Arrow 15.
  Velox vendors the older `RleDecoder`. Its `GetBatchWithDictSpaced` is
  structurally different — `DictionaryConverter` is a plain struct with no
  validating constructor, and all-null blocks are filled without touching the
  dictionary — so it is not exposed to the empty-dictionary crash the upstream
  guard prevents. The truncation-tolerance change has no counterpart to port.
- Column/offset index UB and crash-on-invalid-data — GH-48146, GH-48308. These
  harden Arrow's page-index *reader*. Velox's production reader does not use the
  page index (the vendored `PageIndexReader` is test-only), so there is no
  production path to harden here.

**P1 — statistics / index quality (writer-applicable):**

- **Already present.** Per-column `pageIndexEnabled`/`statisticsEnabled` live in
  `Properties.h`, and the writer already builds and writes the page index
  (`PageIndexBuilder`, `ColumnIndexBuilder`, `FileWriter::writePageIndex`). The
  fork tracks Arrow past the point where these were added, so no port is needed.
  `CopyColumnSpecificProperties` is a convenience method of marginal value.
- **Size statistics — a dedicated PR (in progress).** The feature is absent from
  the fork and spans several files across the FBThrift boundary. It is being
  landed incrementally:
  1. **[Done]** `parquet.thrift`: `SizeStatistics` struct and
     `ColumnMetaData.size_statistics` (id 16); regenerated via FBThrift.
  2. **[Done]** Vendored `SizeStatistics.{h,cpp}` (rehomed) with level-histogram
     and unencoded-byte accounting, plus a `SizeStatisticsLevel` writer property
     defaulting to `kNone` (no behavior change).
  3. **[Done]** `ColumnWriter.cpp`: holds a per-chunk `SizeStatistics`
     (`SizeStatistics::make(descr_)` when the level is `kColumnChunk`) and calls
     `updateLevelHistogram` over the def/rep levels off the level-writing path,
     setting it on the column metadata in `close()`.
  4. **[Done]** `Metadata.cpp`: `ColumnChunkMetaDataBuilder::setSizeStatistics`
     writes the FBThrift `size_statistics` field, and
     `ColumnChunkMetaData::sizeStatistics()` reads it back.
  5. **[Done]** Test: writes an optional column with `kColumnChunk` and asserts
     the definition level histogram round-trips for every primitive type.
  6. **[Done]** Unencoded BYTE_ARRAY byte accounting: the writer sums the
     unencoded value lengths (packed and spaced paths) into
     `unencodedByteArrayDataBytes`, verified by a round-trip test.
  7. **[Done]** Page-level level histograms. `DataPage` carries a
     `SizeStatistics`; the column writer accumulates a per-page snapshot and
     resets it at each page build; the page writer feeds it to
     `ColumnIndexBuilder::addPage`, which concatenates the definition and
     repetition level histograms into the `ColumnIndex`. Verified by a builder
     test that checks the serialized concatenation order.
  8. **[Remaining]** Unencoded per-page bytes belong in `OffsetIndex` (field 2),
     a further small step. Flipping the default level to match upstream is a
     behavior change and should ship on its own with broad test validation.

**P2 — features (larger, optional):**

- Content-defined chunking (`chunker_internal`).
- `max_rows_per_page` writer control (Arrow 23, GH-47030).
- Geospatial / Variant logical types — only if Velox needs them.

## Per-port methodology

For each backlog item:

1. Locate the upstream change (`git log`/PR in apache/arrow) and the file(s) it
   touches. Reference `/tmp` copies of Arrow 15.0.0 and 23.0.1 parquet-cpp for
   the exact diff.
2. Identify the corresponding Velox file(s) and the surrounding Velox delta
   (namespace, camelCase, FBThrift usage, existing feature code).
3. Apply the semantic change, translated to Velox conventions:
   - Namespace `parquet::` → `facebook::velox::parquet::arrow`.
   - snake_case → camelCase for methods and locals.
   - Any Thrift touchpoint goes through FBThrift (`ThriftInternal.h` /
     `facebook::velox::parquet::thrift`), never Apache Thrift.
   - Preserve Velox feature additions; do not regress them.
4. Write or update a test in `writer/arrow/tests/` that fails before the change
   and passes after.
5. Validate the full writer suite plus the native reader suite against Arrow 23.

## Constraints and risks

- **FBThrift boundary.** Any upstream change that adds or alters Thrift
  serialization must be reworked onto FBThrift. Metadata/PageIndex ports are the
  most exposed.
- **Regression baseline.** The current fork passes 564 writer tests + the reader
  suites on Arrow 23. Every port must keep them green.
- **Feature preservation.** Byte-based flush, Iceberg statistics, and INT96
  handling are Velox-only and must survive each port.
- **Scope creep.** `column_writer.cc`'s large diff is dominated by
  size-statistics, geospatial, and variant additions. Port only what Velox
  needs; do not pull the entire upstream surface.

## Phasing

1. This document + P0 correctness ports (small, high value).
2. P1 statistics/index quality.
3. P2 features, each gated on a concrete Velox need.

Each phase is one or more reviewable PRs. The fork stays FBThrift-based and
continues to compile against the linked Arrow 23 `libarrow` throughout.
